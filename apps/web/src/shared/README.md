# shared

Generic, business-agnostic building blocks usable by literally any other
layer. Rule of thumb: if you can imagine reusing this exact file in a
completely unrelated app, it belongs here. The moment it needs to know
what a "Todo" or a "User" is, it has leaked out of `shared` and belongs in
`entities` or `features`.

`shared` has no slices — only segments. Segments may freely import each
other freely.
Nothing above may be imported *into* `shared`; it sits at the bottom of the
stack.

## Segments

- `ui/` — dumb UI primitives with zero domain knowledge: `Button`, `Input`,
  and accessible components generated by the shadcn CLI on top of Base UI
  (`Dialog`, `DropdownMenu`, `Tooltip`). Built with `class-variance-authority`
  for variants + `cn()` for merging — see `ui/button.tsx` for the hand-written
  pattern to copy for a new primitive that isn't in the shadcn registry.
  Need another accessible component (select, combobox, tabs, popover)?
  `bunx shadcn@latest add <component>` — `components.json`'s aliases already
  point at `shared/ui`/`shared/lib`, so it lands in the right place with the
  right imports. Base UI components compose via a `render` prop, not Radix's
  `asChild` — e.g. `<DialogTrigger render={<Button variant="ghost" />}>...`.
- `api/` — the typed oRPC `client`, its TanStack Query helpers `orpc`, and
  the single `queryClient`. Every slice talks to the backend through `orpc`
  from here (types come from `@app/contract`) — never a hand-written `fetch`.
- `lib/` — small pure utility wrappers: `cn` (clsx + tailwind-merge),
  `dayjs` (pre-configured with the `relativeTime` plugin + `ko` locale).
- `config/` — not present yet. If you ever need a `VITE_*` env var, create
  `config/env.ts` with a zod schema and read it only from there.
- `hooks/` — reusable hooks that don't fit `usehooks-ts`'s generic set
  (this is also where the shadcn CLI drops any hook a generated component
  needs, e.g. `use-mobile`). Empty until something actually needs it —
  don't create a hook here speculatively.

## Before writing a new helper here — check first

This template already pulls in libraries for the things that are usually
hand-rolled per-project. Reach for these before adding a new file to
`shared/lib`:

| Need                                   | Use                              |
| --------------------------------------- | --------------------------------- |
| debounce/throttle, groupBy/pick/omit    | `es-toolkit`                     |
| useLocalStorage, useDebounce, useMediaQuery, useClickOutside | `usehooks-ts` |
| dates/relative time                     | `dayjs` (`shared/lib/dayjs.ts`)  |
| form state + validation                 | `react-hook-form` + `zod` (`@hookform/resolvers/zod`) |
| toast notifications                     | `sonner`'s `toast(...)` directly — `<Toaster />` is already mounted in `app/providers` |
| conditional/merged Tailwind classes     | `cn()` (`shared/lib/cn.ts`)      |
| tailwind style variants (e.g. a button's `variant`/`size` props) | `class-variance-authority` |

If none of these cover it and the helper is truly generic, add it to
`shared/lib` and export it from `shared/lib/index.ts`.
